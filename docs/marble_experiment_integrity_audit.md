## 5. Result Consistency

### SMTR-TCI Reward (main experiment)
| Method | Reward | Groups | Injected |
|--------|--------|--------|----------|
| SMTR-TCI | 0.670 | 118 | 0.3 |
| Heuristic | 0.415 | 118 | 2.8 |
| No Memory | 0.373 | 118 | 0.0 |

**Consistency check**: SMTR injects only 0.3 memories/group (most groups have no positive_transfer memories). High reward comes from selective injection of truly beneficial memories.

### Contamination Results
| Method | r=0.2 Retention | r=0.3 Retention |
|--------|----------------|----------------|
| SMTR-TCI | 0.000 | 0.000 |
| Full Memory | 0.432 | 0.602 |

**Integrity issue**: SMTR zero retention is guaranteed by design (selects only `positive_transfer`, never selects contaminated `neutral_*`).

## Recommendations

### Must-Fix Before Paper Submission

1. **Clarify SMTR-TCI as upper bound**: The +61.2% improvement uses ground-truth labels. Present as "TCI oracle upper bound" not "TCI model performance."

2. **Expand scenario coverage**: Run at least 2 more MARBLE scenarios (coding, research) to support cross-domain claims.

3. **Run multi-receiver**: Execute agent2 and agent3 to validate receiver-conditioned claims.

4. **Add more seeds**: 3 seeds is borderline. Run seeds 3 and 4 for stronger statistics.

### Nice-to-Have

5. **Real TCI model**: Replace ground-truth label proxy with actual trained TCI classifier.
6. **Full 500-task run**: If budget allows, expand to all database tasks.
7. **Cross-backbone validation**: Test with GPT-4.1 and Llama-3.1-70B.
