模块以 `graph.py` 为入口，使用 `langgraph.graph.StateGraph(SMTRState)` 构建固定 DAG：START → pre_route_planner → planner → pre_route_executor → executor → pre_route_critic → critic → END；每个业务节点前插入 `_pre_route_node` 包装器，负责从 `SharedMemoryRepository` 拉取路由卡片、调用 `CandidateProposer` 生成候选、再由 `MemoryRouter` 决策并记录 `RouterTraceEntry`。

- 状态契约：`state.py` 定义 `SMTRState` TypedDict，所有节点通过读写该字典传递上下文（含 `agent_local_context.visible_payloads`、`candidate_memory_ids_by_agent`、`router_trace` 等）。
- 代理层：`agents.py` 实现 `run_planner/run_executor/run_critic`，默认回退到 `fake_llm.DeterministicFakeLLM`；`marble_agent.py`、`tau3_agent.py` 提供额外 agent 变体。
- 环境抽象：`environment.EnvironmentAdapter` Protocol 统一 `observe/snapshot/restore/apply`，`ToyEnvironment`（带 normal/resource_constrained/adversarial 三种模式）和 `tool_environment.ToolEnvironment`（注册表驱动的工具集合）均实现该协议，由 `env_factory` 注入。
- LLM 抽象：`real_llm.RealLLM` 同时支持本地 transformers+BitsAndBytes 8bit 加载与远程 OpenAI 兼容 HTTP API（httpx），对外暴露 `plan()/summarize_execution()` 与 FakeLLM 一致接口。
- 外部集成：`api_server.py` 用 FastAPI 暴露 `/v1/chat/completions`、`/smtr/demo`、`/smtr/run-pipeline`、`/health`，并通过全局 `_llm_instance` 与 `set_env_factory` 做依赖注入；`delegation_topology.py` 提供独立的 DelegationGraph/DAG 验证与 `ScopedMemoryView` 可见性过滤，当前未被 graph 直接引用，作为扩展能力存在。
- 依赖方向：runtime → smtr.config / smtr.router.* / smtr.memory.* / smtr.counterfactual.decision_points；反向不被其他子包依赖，仅被上层 `smtr.runtime` 包导出 `build_graph`、`run_demo`。
