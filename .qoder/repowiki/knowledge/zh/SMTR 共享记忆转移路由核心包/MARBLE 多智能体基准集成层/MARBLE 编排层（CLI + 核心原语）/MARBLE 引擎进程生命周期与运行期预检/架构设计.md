本模块由三个职责正交的 Python 文件组成，共同构成 SMTR 调用真实 MARBLE 引擎的“进程外壳”：
- `engine_process.py` 是核心边界：通过 `subprocess.Popen(..., start_new_session=True)` 以独立进程族启动 `marble/main.py`，使用 `_engine_environment` 注入 PYTHONPATH（含动态写入的 `sitecustomize.py` shim）并桥接 DashScope → OpenAI 兼容环境变量；超时后按 SIGTERM→SIGKILL 两阶段终止进程组，随后清理 Docker Compose DB 容器；对 stdout/stderr 做正则脱敏后再落盘，并以 JSONL 形式解析 raw_result 进行存在性/新鲜度/可解析/身份一致性校验，最终汇总到不可变 `MarbleEngineProcessResult` dataclass。
- `runtime_preflight.py` 提供 `run_database_runtime_preflight` / `write_runtime_preflight`，以 `RuntimeCheck` + `MarbleRuntimePreflightResult` 数据结构逐项探测 Python 版本(≥3.9,<3.13)、Docker/Docker Compose、端口 5432、sudo -n、关键包导入、LLM API Key/Model/Base URL，blocking 项全部通过才标记 ready。
- `engine_audit.py` 仅做静态扫描：读取 `db_env.py`/`engine.py`/`evaluator.py`/`main.py` 是否存在及源码片段，生成一份描述引擎入口、任务加载器、副作用的 JSON 摘要，供上层决策是否允许 real_engine_execution。

依赖方向单向向外：本模块只读 `smtr.marble.artifacts.assert_marble_artifact_path` 和 `smtr.counterfactual.decision_points.canonical_digest`，被上层编排器调用，不反向依赖 MARBLE 内部实现。
