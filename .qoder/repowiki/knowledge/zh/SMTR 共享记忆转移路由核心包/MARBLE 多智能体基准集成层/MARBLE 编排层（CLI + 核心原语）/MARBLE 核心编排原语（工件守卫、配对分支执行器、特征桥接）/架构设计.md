本模块由三个职责正交的单文件原语组成，共同构成 MARBLE 对比实验的“执行-产出-消费”链路：
- artifacts.py：定义 `MARBLE_ARTIFACT_ROOT` / `TOY_ARTIFACT_ROOT` 常量及 `assert_*_artifact_path` 守卫函数，作为所有写入 artifact 的入口前置校验，禁止逃逸到根目录之外。
- branch_runner.py：`MarblePairedBranchRunner.run_pair` 是核心编排方法，按 `branch_execution_order` 顺序对 share/withhold 两个分支分别调用 `SequentialDatabaseRebuilder.materialize` 重建环境、`MarbleDatabaseEnvironment.run` 执行引擎、`evaluator_for_scenario` 评估结果，并用 `_validate_pair` 校验两分支初始指纹、digest、清理状态与非内存输入段一致性，最终输出冻结的 `PairedBranchResult` 并持久化为 `branch_audit.json`。
- feature_bridge.py：纯转换层，把 MARBLE 侧的 `RealPaiedRecord` / `ProceduralRoutingCard` 映射到 SMTR 侧 `PairedInterventionRecord` / `RoutingFeatureSnapshot` / `ContextFingerprint`，供 critic 训练消费；通过 `_digest_str` 生成稳定短摘要，通过 `_slugify` 规范化风险键。
依赖方向单向向外：branch_runner → artifacts + environment + memory_injection + outcome；feature_bridge → counterfactual.schemas + marble.real_data + memory.schemas，三者互不耦合。
