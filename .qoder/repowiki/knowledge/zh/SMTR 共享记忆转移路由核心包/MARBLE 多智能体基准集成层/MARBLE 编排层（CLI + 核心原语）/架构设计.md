- `cli.py` 是唯一的用户入口，按子命令把各子模块的顶层函数/类装配成端到端工作流：`inspect-dataset` → `create-splits` → `generate-paired-records` / `collect-database-trajectories` → `extract-database-memories` → `build-database-candidates` → `generate-database-paired-records` → `train-critic` → `run-evaluation` → `integrity-audit`。
- 子模块之间不直接互相 import，而是通过磁盘上的 JSON 清单（dataset manifest、split manifest、pilot manifest、candidate manifest、memory pool、paired records、checkpoint）作为跨进程契约；每个子命令只消费上一阶段的输出文件，形成单向 DAG。
- 共享原语集中在本层：`artifacts.py` 提供工件根目录守卫，`branch_runner.py` 驱动 share/withhold 分支执行，`feature_bridge.py` 将 MARBLE 记录桥接为 SMTR 训练输入，`engine_process.py` 封装外部引擎子进程边界，`environment/` 与 `outcome/` 分别定义场景环境协议与结果协议，被 database 场景的子模块复用。
- 数据库场景的冒烟、rebuild 校验、paired smoke/pilot 由 `database_smoke.py` 与 `database_pilot.py` 组合，统一走 `MarbleDatabaseEnvironment` + `bundle_from_manifest_task` 构建初始状态包，确保真实引擎与隔离环境的可复现性。
