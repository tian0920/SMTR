模块由三个职责清晰的子文件组成，依赖方向单向：`splits.py` → `real_data.py` → `real_workflows.py`。
- `splits.py`：只读的数据集切分器。通过 `create_split_manifest` 读取数据集 manifest，按 `schema_family_digest`（或回退到 `init_sql_digest`）对 task 分组后以固定 seed 随机打乱并切割为 train/validation/test，输出带 `dataset_manifest_sha256`、`smtr_commit` 等元数据的 `MarbleSplitManifest`；`validate_split_manifest` 保证三集合互斥且覆盖全集、同组不泄漏。
- `real_data.py`：纯数据层，用 Pydantic `BaseModel(frozen=True)` 声明不可变契约——`RealDatabaseTrajectory`（单条轨迹）、`RealProceduralMemory`（从轨迹提取的程序化记忆）、`DatabaseCandidateManifest` + `CandidateSet`（跨任务候选）、`RealPairedRecord`（干预配对）。所有业务约束集中在 `@model_validator(mode="after")` 中实现（如 valid/failure_reason 互斥、tau=Y_share-Y_withhold、禁止答案泄露 token 等），并提供无副作用的 `build_cross_task_candidates`（基于路由卡词袋 Jaccard 召回 top-k）和 `extract_procedural_memories`（仅允许 train split）。
- `real_workflows.py`：可执行工作流入口。`collect_database_trajectories` 作为唯一对外 API，加载 dataset/split manifest 并校验哈希，遍历 selected tasks × generation_seeds，调用 `run_database_b0_smoke` 驱动真实引擎，成功时经 `_normalize_smoke`+`_structured_trace` 产出 `RealDatabaseTrajectory`，失败时写入 `valid=False` 的兜底 payload（保留错误以便分析），最终汇总写 `trajectory_index.jsonl`。`_failure_reason` 将运行时状态归一化为有限枚举（preflight_failed/engine_timeout/engine_failed/raw_result_invalid/trace_missing/evaluator_failed/unknown）。

边界：本模块不直接访问外部数据库，仅消费 `smtr.marble.database_smoke` 产出的 JSON 摘要；所有持久化产物均含 schema_version 与 sha256 指纹，供下游反事实评估使用。
