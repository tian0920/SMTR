本模块由三个职责清晰的脚本组成，围绕 database 场景的端到端验证：
- `memory_injection.py` 暴露纯函数式接口 `MarbleMemoryInjector.build_agent_input`，在不修改 system/task/tools 的前提下按需注入 memory section，并通过不可变 `MarbleAgentInputAudit` dataclass 记录各段 digest，供 share/withhold 分支做输入一致性断言。
- `database_smoke.py` 提供三类入口：`run_database_b0_smoke`（无记忆基线运行）、`verify_database_rebuild`（通过 `SequentialDatabaseRebuilder` 两次 materialize + marker 文件检测隔离性）、`run_database_paired_smoke`（调用 `MarblePairedBranchRunner.run_pair` 对比 share/withhold）。所有路径均经 `assert_marble_artifact_path` 校验，结果以 JSON 落盘并返回 summary dict；LLM 模型选择遵循 `MARBLE_LLM_MODEL` / `OPENAI_MODEL` / `DASHSCOPE_MODEL` 环境变量回退链。
- `database_pilot.py` 基于 `MarbleTaskProvider` 从 dataset/split manifest 抽取 database 任务，用 `_memory` 构造 helpful/harmful/irrelevant 三组候选记忆生成 pilot manifest，再由 `run_database_paired_pilot` 遍历 manifest 批量执行 paired run，汇总 label_counts 与 invalid_count 写入 `pilot_summary.json`。
依赖方向单向：smoke/pilot → memory_injection → marble 核心（branch_runner、environment、task_provider、runtime_preflight），本模块不反向依赖上层编排器。
