本模块由三个职责正交的文件组成：
- `dataset.py` 是纯数据发现层，通过 `discover_marble_benchmark_tasks` 读取 `marble_root/multiagentbench/<scenario>/*_main.jsonl`（由 `MARBLE_BENCHMARK_FILES` 白名单限定），将每条 JSONL 行解析为冻结的 `MarbleTaskManifestRecord`，再由 `build_marble_dataset_manifest` / `write_marble_dataset_manifest` 组装成 `MarbleDatasetManifest` 清单；对 database 场景额外校验 task_id 唯一性、init_sql 存在性，并通过 `_schema_statements` 抽取 SQL schema 指纹，同时用 `subprocess.run(['git', ...])` 抓取 marble 与 smtr 仓库的 commit 与时间戳。
- `paired_records.py` 提供 `MarblePairedRecordGenerator.generate`，面向 pilot 隔离实验：从 `MarbleTaskProvider.iter_split` 拉取任务，调用 `_pilot_candidate_memory` 构造固定格式的候选记忆，再用 `bundle_from_manifest_task` 打包初始状态，委托 `MarblePairedBranchRunner.run_pair` 并行运行 share/withhold 两条分支，最终按 `base_episode_id` 写入 `workspaces/` 目录并在输出根目录落盘 `paired_records.jsonl` 与 `summary.json`。
- `real_pairs.py` 提供 `generate_real_database_pairs`，面向真实跨任务配对：先加载 dataset manifest、候选集 JSON 与 `memory_pool_path`（`RealProceduralMemory` JSONL），展开 candidate→memory 边后逐条调用 `runner.run_pair`，并将结果封装为 `RealPairedRecord` 写入 `pairs/<pair_id>/` 工作区与 `paired_records.jsonl`；失败路径统一捕获异常并以 `failure_reason` 字段记录。
依赖方向单向向下：两个 generator 都只消费 `task_provider`、`branch_runner`、`environment.isolation.bundle_from_manifest_task` 以及 `counterfactual.decision_points.canonical_digest`，不反向引用 `dataset.py` 的清单模型，从而保持“清单构建”和“配对执行”两层解耦。
