本模块提供三个面向 MARBLE 数据集的独立入口，均位于 `smtr.marble` 包顶层，通过 `feature_bridge` 与 `real_data` 把 MARBLE JSONL 适配到 SMTR 内部类型：
- `training.py` 中的 `MarbleTrainingPipeline.train` 读取 `RealPairedRecord` JSONL 与 `RealProceduralMemory` 池，经 `_bridge_records` + `marble_record_to_training_input` 转为 `PairedInterventionRecord`，用 `HashingTransferFeatureEncoder` 构造特征并拟合 `FourOutcomeTransferCritic` 集成（默认 31 棵 bootstrap 树），输出字节级兼容 checkpoint 及 `.metadata.json`、`.metrics.json`。
- `evaluation.py` 中的 `MarbleExperimentRunner.run` 加载已训练 critic 与 `SMTRGate`，对 split manifest 中每个 test record 生成 `TransferPredictionInput`，调用 `critic.predict_point` + `gate.decide(tau_hat > 0 and eta_hat <= epsilon)` 做正式门控，同时计算 b0_no_memory / all_share 两条基线，汇总 share/withhold 比率写入 JSON。
- `integrity.py` 提供两个审计函数：`audit_marble_pilot_run` 扫描 run_dir 下各子目录的 `paired_summary.json` 聚合有效性标志与标签分布；`audit_marble_pilot` 作为旧格式回退，直接统计 paired_records_path 的 valid/invalid 行数。
依赖方向单向指向 `smtr.router.*`（critic/gate）与 `smtr.counterfactual.schemas`，本模块不反向被 router 依赖，仅作为 MARBLE 侧的数据适配与编排层。
