模块按职责划分为四层：
- 协议层 `protocol.py` 定义 `MarbleEnvironmentInstance` / `MarbleEnvironmentFactory` 两个 typing.Protocol，作为上层调用方与具体实现的稳定边界。
- 核心隔离层 `isolation.py` 通过 Pydantic `InitialStateBundle`（frozen）描述不可变初始状态，并提供 `materialize_bundle_workspace` 将 bundle 中的 `workspace_template` 写入目标目录、生成 `bundle.json` 和基于 `canonical_digest` 的工作区快照摘要；`_schema_lines`/`_content_lines` 从 SQL 中抽取 DDL/DML 行用于独立摘要。
- 场景实现层 `scenarios/database.py` 提供真实 `MarbleDatabaseEnvironment`，对上游 MARBLE 的 DBEnvironment 做 fail-fast 预检（检查固定 docker-compose 路径与 localhost:5432），拒绝当前无法隔离的 paired 分支；`factory.py` 中的 `DatabaseFilesystemEnvironmentFactory` + `FilesystemMarbleEnvironmentInstance` 是面向 pilot 的轻量文件系统实例，仅写 `run_input.json` 并返回记录。
- 辅助工具层 `database_fingerprint.py` 提供 `DatabaseLogicalFingerprint`（schema/content/config/combined 四段 digest）与 SQL 规范化函数；`database_rebuild.py` 的 `SequentialDatabaseRebuilder` 串联 materialize → fingerprint → 通过 `sudo docker compose down -v` 销毁容器卷的完整生命周期。
依赖方向单向：`scenarios/database` → `isolation`；`database_fingerprint` / `database_rebuild` → `isolation`；`factory` → `isolation`；所有层均不反向依赖彼此，仅通过 `smtr.counterfactual.decision_points.canonical_digest` 统一哈希。
