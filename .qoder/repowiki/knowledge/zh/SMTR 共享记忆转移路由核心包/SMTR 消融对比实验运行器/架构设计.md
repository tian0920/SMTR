模块以 `runner.ComparisonRunner` 为唯一入口，按“先跑完所有基线 B0 → 再遍历方法 × 基线 × traversal_seed”的固定顺序执行，并通过 `writer.ExperimentWriter` 将每条完整 run 追加到 `runs.jsonl`，最后断言 roundtrip 一致性。

内部分层：
- 配置与数据契约：`schemas.py` 用 Pydantic frozen BaseModel 定义 `ExperimentConfig`、`ComparisonRunRecord`、`RoutingInvocationRecord`、`DecisionRecord`、`MethodSummary`、`ExperimentSummary` 等不可变记录结构；`methods.py` 维护 `MethodSpec` dataclass 注册表（含 `METHOD_REGISTRY`、`ABLATION_METHODS`）与 display ↔ registry key 的双向映射，由 `build_default_specs` 注入 checkpoint/budget 路径。
- 运行时编排：`runner.py` 通过 `_build_router_for_method` 把方法名分派到 `NoMemoryRouter` / `RelevanceTopKRouter` / `BudgetMatchedTopKRouter` / `ProductionSequentialRouter`（含 EffectOnly/Static/FactualSuccess 门控变体），并用 `_RankPermutationTraversal` 支持显式候选排序。
- 统计与诊断：`summary.py` 聚合每方法的 success/transfer/rejection/opportunity_capture/safety_preservation 指标并计算 paired bootstrap CI；`paired_comparisons.py` 独立实现按 base episode 分组的配对 bootstrap；`budget_manifest.py` 从 M0 验证集导出 `ShareBudgetManifest` 供 B1-Matched 采样预算；其余文件 (`bottleneck_funnel.py`, `candidate_diagnostics.py`, `prefix_trace.py`, `rejection_analysis.py`) 提供面向下游分析器的辅助 JSON 产出。
- I/O：`writer.py` 统一写入 config/runs/errors/invocations/decisions/scenario_slices/paired_comparisons/bottleneck_funnel 等 JSONL/JSON 产物，并提供 `load_runs()` 用于 roundtrip 校验。

依赖方向单向向外：本模块仅消费 `smtr.router.*`、`smtr.evaluation.*`、`smtr.memory.*`、`smtr.runtime.*`、`smtr.counterfactual.*` 的构建 API，不反向被它们引用。
