模块按职责分为三层：
- 声明层 `schemas.py` + `fingerprints.py`：用 Pydantic `frozen=True` 的 `ContinuationPolicyManifest` 描述策略元数据，并通过 `canonical_json` + `sha256_text` 生成不可变指纹；`validate_policy_manifest` 按 `policy_kind` 分支校验必填字段并可选校验本地 checkpoint 的 sha256。
- 持久化层 `manifests.py`：仅暴露 `load_policy_manifest` / `save_policy_manifest` 两个 I/O 函数，对上层屏蔽 JSON 序列化细节。
- 策略实现层：三个不可变策略类分别对应三种 `policy_kind`——`FrozenNoShareContinuationPolicy`（直接返回 withhold）、`FrozenCriticSequentialContinuationPolicy`（调用 `FourOutcomeTransferCritic.predict` 后走 `strict_lcb_ucb_gate`）、`FrozenRiskConstrainedExplorationPolicy`（基于稳定哈希 `_stable_unit_interval` 构造确定性 score，再按 safe_exploit / boundary_explore / risk_veto 等模式分流），均通过 `decide(...)` 返回 `RouterDecision` 或字符串动作。
- 在线刷新层 `online_refresh.py`：`OnlinePolicyRefresher` 以 `RefreshTrigger`（record_count / uncertainty / time_elapsed / manual）驱动，结合 `OffPolicyCorrector` 做离策校正后再 `fit` 新的 `FourOutcomeTransferCritic`，并以原子替换保证安全；`ActiveDataAcquisition` 则依据 tau UCB-LCB 不确定性或边界区域挑选待采集样本。
依赖方向单向向外：策略 → manifests/schemas → router.causal_gate / router.transfer_critic；online_refresh 不反向依赖策略类，仅消费 critic 接口。
